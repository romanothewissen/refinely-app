# Plan: Remove BYOK Barrier — Add Managed AI Provider Strategy

## Problem Assessment

**Zero installs in one week** on the Atlassian Marketplace is likely caused by multiple compounding friction points:

1. **BYOK is the #1 killer.** Before users can do anything with the app, they must: (a) create an account on an AI provider platform, (b) add billing info, (c) generate an API key, (d) paste it into Refinely settings. This is a 10+ minute setup with a credit card commitment before they see any value.
2. **Settings-first UX.** The onboarding flow sends users to Settings before they can use the product. There's no "try it now" path.
3. **Cost uncertainty.** Users don't know how much API calls will cost them. Gemini Flash is cheap but users don't know that — they see "API key required" and bounce.
4. **No free-tier value demo.** The Free tier gives 5 generations, but even those require BYOK setup first.

## Recommended Strategy: Managed Key via OpenRouter + Gemini Flash

### Why OpenRouter as the managed provider

| Criteria | Direct Gemini API | OpenRouter | Azure OpenAI |
|---|---|---|---|
| **API compatibility** | Different endpoint format | OpenAI-compatible (drop-in) | OpenAI-compatible but needs deployment names |
| **Single key, multi-model** | Gemini only | 300+ models, single key | OpenAI models only |
| **Free tier available** | No | Yes (25+ free models) | No |
| **Cost markup** | None | ~5.5% platform fee (no model markup) | Azure markup |
| **Prompt caching** | Yes (context caching) | Yes | No |
| **Pay-as-you-go** | Yes | Yes (buy credits) | Enterprise commitment |
| **Forge remote host** | Already declared | New declaration needed | Not declared |

**Key insight:** OpenRouter's API is OpenAI-compatible (same `/v1/chat/completions` endpoint), which means we can reuse the existing `callOpenAI` function with a different base URL. This dramatically reduces implementation scope.

### Why Gemini Flash as the default managed model

Your current pipeline already uses Gemini Flash for discovery/refinement roles. It's:
- **Extremely cheap**: ~$0.10/M input, $0.40/M output (Gemini 2.5 Flash pricing)
- **Very capable**: Handles clarify, evaluate, triage, theme roles well
- **Fast**: Low latency for interactive clarification flow
- **Cost per generation estimate**: A typical Refinely generation uses ~15K-25K tokens total across all pipeline stages. At Gemini Flash prices, that's roughly **$0.005-$0.015 per generation**. Even at 150 generations/month per Standard user, that's **$0.75-$2.25/user/month** in API costs.

For the pro/quality pipeline stages (decomposition, AR writing), Gemini 2.5 Pro at ~$1.25/M input, $10/M output still comes out to approximately $0.05-$0.10 per generation for the heavy-lifting stages.

### Ollama Cloud consideration

Ollama now offers cloud models (as of Sept 2025), but:
- It's still in preview
- Pricing is less transparent
- The existing Ollama support in your codebase is designed for self-hosted (BYOK with base URL)
- **Not recommended** as the primary managed provider — keep Ollama as the self-hosted option for privacy-conscious users

## Implementation Plan

### Phase 1: Add OpenRouter as a "Managed" Provider (Core Infrastructure)

**Goal:** Users can install the app and immediately start refining without any API key. The app uses an OpenRouter API key stored as a Forge environment variable (app-level secret shared across all tenants).

#### 1.1 Add `openrouter` as a new `LlmProvider`

**Files to modify:**
- `src/types.ts:9` — Add `'openrouter'` to `LlmProvider` union
- `src/frontend/src/types.ts:9` — Same

#### 1.2 Implement `callOpenRouter` in `src/core/llm.ts`

Since OpenRouter uses the OpenAI-compatible API (`https://openrouter.ai/api/v1/chat/completions`), create `callOpenRouter()` that:
- Extends `callOpenAI` with OpenRouter-specific headers (`HTTP-Referer: smartif.ai`, `X-OpenRouter-Title: Refinely`)
- Reads key from `opts.openrouterApiKey ?? process.env.OPENROUTER_API_KEY ?? ''`
- Maps model names if needed (OpenRouter uses `provider/model` format, e.g. `google/gemini-2.5-flash`)
- Add to the `callLlm` routing switch

#### 1.3 Add OpenRouter to `manifest.yml` remote hosts

```yaml
- address: https://openrouter.ai
```

#### 1.4 Add OpenRouter to the model catalog

**File:** `src/frontend/src/modelStrategyCatalog.json`

Add an `openrouter` provider section with the managed model lineup:
- **pro**: `google/gemini-2.5-pro` (competes with your current Gemini Pro usage)
- **flash**: `google/gemini-2.5-flash` (your current workhorse)
- **lite**: `google/gemini-2.0-flash-lite` (for free-tier downgrades)

Also add cross-provider options for future:
- **pro-alt**: `anthropic/claude-sonnet-4`, `openai/gpt-4.1`
- **flash-alt**: `anthropic/claude-haiku-4.5`, `openai/gpt-4o-mini`

#### 1.5 Revive `forge_llms` as the "Managed" sentinel

Instead of creating a new concept, repurpose the existing `forge_llms` provider:
- When `provider === 'forge_llms'`, normalize to `'openrouter'` (not `'anthropic'`)
- Remove the empty-catalog stubs; return the OpenRouter catalog
- In `callLlm`, route `forge_llms` → `callOpenRouter`
- In Settings UI, show it as "Refinely Managed AI (recommended)" — no key entry needed

This preserves backward compatibility and uses an existing concept.

#### 1.6 Set the OpenRouter API key as a Forge environment variable

```bash
forge variables set OPENROUTER_API_KEY sk-or-v1-xxxxx -e production
```

The existing `process.env.OPENROUTER_API_KEY` fallback in `callOpenRouter` will pick this up automatically when tenants haven't configured their own key.

### Phase 3: Cost Controls & Billing Integration

**Goal:** Ensure managed AI costs don't exceed subscription revenue.

#### 3.1 Add per-tenant token cost tracking

**File:** `src/services/billing.ts`

Extend `UsageRecord` to include:
```ts
interface UsageRecord {
  month: string;
  generations: number;
  managedInputTokens: number;
  managedOutputTokens: number;
}
```

Record token usage from `TokenUsageSummary` after each generation. This gives you visibility into actual per-tenant cost.

#### 3.2 Enforce managed model restrictions by tier

**File:** `src/services/billing.ts` — Extend `getTierModel()`:

- **Free tier**: Force `google/gemini-2.0-flash-lite` for all roles (cheapest)
- **Standard tier**: Allow `google/gemini-2.5-flash` for discovery + `google/gemini-2.5-pro` for generation
- **BYOK users**: No model restrictions (their key, their cost)

#### 3.3 Hard-enforce the free tier generation cap for managed key users

Currently `checkGenerationAllowed` always returns `allowed: true`. For managed-key tenants on the free tier, actually block generation at the limit (5 generations), since each generation now costs you real money.

For Standard (paid) tenants, keep the soft limit since they're paying for the service.

#### 3.4 Add cost monitoring dashboard (internal)

Add a resolver that aggregates per-tenant managed token usage for your own monitoring. Not exposed to users — just for you to track burn rate vs. subscription revenue.

### Phase 5: Future Enhancements (Post-Launch)

These are NOT in scope for the first iteration but are noted for roadmap:

- **@forge/llm integration**: The `@forge/llm` package is already installed. If Atlassian ships a production-ready Forge LLM proxy, switch from OpenRouter to that for even tighter integration and possibly lower latency.
- **Adaptive model routing**: Use OpenRouter's routing to automatically fall back from Gemini Flash to Claude Haiku if Google is rate-limiting.
- **Token-based pricing tier**: If costs scale, consider a "tokens per month" limit instead of "generations per month" for more precise cost control.
- **Ollama Cloud**: Monitor Ollama's cloud offering maturity; could be an alternative managed provider for privacy-focused positioning.

## Cost Projection

### Per-user managed AI cost (Standard tier, 150 generations/month)

| Pipeline Stage | Model | Avg Tokens/Gen | Cost/1K Tokens | Est. Cost/User/Mo |
|---|---|---|---|---|
| Clarify | gemini-2.5-flash | ~3K input + 1K output | $0.075/$0.30 | ~$0.003 |
| Triage/Evaluate | gemini-2.5-flash | ~2K input + 500 output | $0.075/$0.30 | ~$0.001 |
| Decomposition | gemini-2.5-flash (balanced) or gemini-2.5-pro (quality) | ~5K input + 2K output | $0.075/$0.30 (flash) or $1.25/$5.00 (pro) | ~$0.001 (flash) or ~$0.016 (pro) |
| AR Writing | gemini-2.5-pro (balanced/quality) | ~8K input + 3K output | $1.25/$5.00 | ~$0.075 |
| Refine | gemini-2.5-flash | ~3K input + 1K output | $0.075/$0.30 | ~$0.003 |
| **Total (balanced)** | | | | **~$0.08/user/mo** |
| **Total (quality)** | | | | **~$0.12/user/mo** |

With OpenRouter's 5.5% fee, add ~$0.01. **Total managed AI cost at 150 gens/mo: ~$0.09-$0.13/user/month.**

At $5/user/month (Standard pricing), your margin is **$4.87-$4.91/user/month**.

Even with generous 3x safety margin assumptions, cost stays under $0.40/user/month.

### Free tier cost exposure

At 5 generations with gemini-2.0-flash-lite (~$0.015/1K input, $0.06/1K output), each free user costs you **less than $0.01/month**. This is negligible and worth the conversion value.

## Key Decision Points

Before implementation, I need your input on:

1. **OpenRouter vs. direct Gemini**: OpenRouter adds 5.5% fee but gives you model flexibility and a single integration point. Direct Gemini API is cheaper but requires a separate `callGemini` code path (which you already have). **Which do you prefer?**
   - Option A (Recommended): OpenRouter — one integration, easy model switching, OpenAI-compatible
   - Option B: Direct Gemini API — use your existing `callGemini`, no middleman, but you're locked to Google models for the managed tier and need to add key management differently (environment variable injection into the existing Gemini code path)

2. **Free tier hard block**: Should the 5-generation free tier cap actually block generation (not just warn) when using managed AI? This protects you from cost abuse. I recommend **yes, hard block for managed key users on free tier**.

3. **Default pipeline profile**: Should managed-key users default to "balanced" (flash for discovery, pro for generation) or "fast" (flash for everything)? "balanced" gives better output quality; "fast" is cheaper. I recommend **balanced** as the default.
